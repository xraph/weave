title: SQLite Store
description: Lightweight SQLite metadata store using Grove with sqlitedriver.
---

The `store/sqlite` package keeps collections, documents and chunks in SQLite through [Grove](https://github.com/xraph/grove) and its `sqlitedriver`. Use it for embedded apps, CLI tools and single-node services that don't want a database server.

## Setup

```go
import (
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/sqlitedriver"

    sqlitestore "github.com/xraph/weave/store/sqlite"
)

sdb := sqlitedriver.New()
if err := sdb.Open(ctx, "weave.db"); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(sdb)
if err != nil {
    log.Fatal(err)
}

st := sqlitestore.New(db)
if err := st.Migrate(ctx); err != nil {
    log.Fatal(err)
}
```

## Migrations

`Migrate` runs `sqlitestore.Migrations` through Grove's migration orchestrator. It creates the same three tables as the PostgreSQL store (`weave_collections`, `weave_documents`, `weave_chunks`) with SQLite column types, and the same unique constraints: collection names per tenant, content hashes per collection.

## Pairing with a vector store

SQLite has no pgvector, so pair it with the in-memory vector store on a single node:

```go
import (
    "github.com/xraph/weave/chunker"
    "github.com/xraph/weave/engine"
    sqlitestore "github.com/xraph/weave/store/sqlite"
    vsmemory "github.com/xraph/weave/vectorstore/memory"
)

eng, err := engine.New(
    engine.WithStore(sqlitestore.New(db)),
    engine.WithVectorStore(vsmemory.New()),
    engine.WithEmbedder(emb),
    engine.WithChunker(chunker.NewRecursiveChunker()),
)
```

The in-memory vectors are gone on restart while the metadata stays. After a restart, call `eng.ReindexCollection` for each collection to rebuild the vectors from the stored chunks, or use a persistent vector store.

## Lifecycle

| Method | Behaviour |
|--------|-----------|
| `Migrate(ctx)` | Applies pending migrations through the orchestrator |
| `Ping(ctx)` | Pings the database |
| `Close()` | Closes the `*grove.DB` |

## When to use it

- Local development, with a single-file database and no server process.
- Tests that want a real SQL store without a container.
- CLI tools, desktop apps and edge deployments.

## Limitations

- SQLite takes a database-wide write lock, so heavy concurrent writes queue up.
- No vector search in the database; you need a separate vector store.
- One process at a time.
