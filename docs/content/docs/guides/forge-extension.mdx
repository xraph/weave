---
title: Forge Extension
description: Mount Weave into a Forge application as a first-class extension with automatic route registration and migrations.
---

The `extension` package wraps the engine as a Forge extension. It builds the engine during `Register`, provides `*engine.Engine` in the DI container, mounts the HTTP routes and runs the store migration on `Start`.

## Registering the extension

```go
package main

import (
    "log"
    "os"

    "github.com/xraph/forge"

    "github.com/xraph/weave/chunker"
    "github.com/xraph/weave/embedder"
    "github.com/xraph/weave/engine"
    weaveext "github.com/xraph/weave/extension"
    "github.com/xraph/weave/store/memory"
    vsmemory "github.com/xraph/weave/vectorstore/memory"
)

func main() {
    app := forge.NewApp(forge.AppConfig{
        Name:        "search-api",
        HTTPAddress: ":8080",
        Extensions: []forge.Extension{
            weaveext.New(
                weaveext.WithStore(memory.New()),
                weaveext.WithVectorStore(vsmemory.New()),
                weaveext.WithEngineOption(engine.WithEmbedder(
                    embedder.NewOpenAIEmbedder(os.Getenv("OPENAI_API_KEY")),
                )),
                weaveext.WithEngineOption(engine.WithChunker(chunker.NewRecursiveChunker())),
            ),
        },
    })

    if err := app.Run(); err != nil {
        log.Fatal(err)
    }
}
```

The extension has no embedder or chunker option of its own. You pass them, and a loader or retriever if you want one, with `WithEngineOption`. You can also register the extension later with `app.RegisterExtension(ext)`.

With the default base path, the routes are at `/weave/v1/...`. The [HTTP API reference](/docs/api-reference/http-api) lists them.

## What the extension does

| Phase | Behaviour |
|-------|-----------|
| `Register` | Loads config, resolves a store from Grove when there is one, builds the engine, mounts the routes (unless `disable_routes`) and provides `*engine.Engine` to the container. Fails when `default_chunk_overlap` isn't smaller than `default_chunk_size`. |
| `Start` | Runs the metadata store's `Migrate` (unless `disable_migrate`). Nothing migrates the pgvector table. |
| `Health` | Pings the metadata store. Fails when there's no store. |
| `Stop` | Calls `engine.Stop`, which fires `OnShutdown` and closes the metadata store. |

`Stop` closing the store means a `*grove.DB` the store was built on gets closed too, including one the extension found in the container and that other extensions share.

## Using a Grove database

When your app registers a `*grove.DB` in the container (usually through the Grove extension), Weave builds its metadata store from it. The driver name picks the store: `pg` gives `store/postgres`, `sqlite` gives `store/sqlite`, `mongo` gives `store/mongo`.

Without any option, the extension looks for the default `*grove.DB` and uses it if it's there. To name one, or to fail at startup when it's missing, use `WithGroveDatabase`:

```go
weaveext.New(
    weaveext.WithGroveDatabase("weave"), // "" means the default database
    weaveext.WithEngineOption(engine.WithEmbedder(
        embedder.NewOpenAIEmbedder(os.Getenv("OPENAI_API_KEY")),
    )),
    weaveext.WithEngineOption(engine.WithChunker(chunker.NewRecursiveChunker())),
)
```

A store built from Grove replaces one you passed with `WithStore`. If there's no Grove database and no `WithStore`, the engine runs without a metadata store and every collection or ingest call returns `weave.ErrNoStore`. There's no in-memory fallback.

The vector store isn't built from Grove. Pass one with `WithVectorStore`, for example `pgvector.New(db)`, or use `fabriqvec.EngineOption(container)` through `WithEngineOption` when Fabriq is in the container.

## Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `WithStore(s)` | `store.Store` | none | Metadata store, replaced by a Grove-built one when Grove is in the container |
| `WithVectorStore(v)` | `vectorstore.VectorStore` | none | Vector store |
| `WithEngineOption(opt)` | `engine.Option` | none | Any engine option: embedder, chunker, loader, retriever, logger, config |
| `WithExtension(x)` | `plugins.Extension` | none | Lifecycle hook, repeatable |
| `WithConfig(cfg)` | `extension.Config` | `extension.DefaultConfig()` | Whole config struct |
| `WithBasePath(path)` | `string` | `"/weave"` | Route prefix |
| `WithDisableRoutes()` | | off | Don't mount the routes |
| `WithDisableMigrate()` | | off | Don't run `Migrate` on `Start` |
| `WithGroveDatabase(name)` | `string` | `""` | Build the store from this named `*grove.DB` |
| `WithRequireConfig(b)` | `bool` | `false` | Fail `Register` without an `extensions.weave` or `weave` config key |

## YAML configuration

The extension reads `extensions.weave`, then the older top-level `weave` key:

```yaml
extensions:
  weave:
    base_path: /weave
    disable_routes: false
    disable_migrate: false
    grove_database: ""
    default_chunk_size: 512
    default_chunk_overlap: 50
    default_embedding_model: text-embedding-3-small
    default_chunk_strategy: recursive
    default_top_k: 10
    shutdown_timeout: 30s
    ingest_concurrency: 4
```

Those are the defaults. `shutdown_timeout` and `ingest_concurrency` are read but nothing uses them yet. `default_embedding_model` and `default_chunk_strategy` are only recorded on new collections. [Configuration](/docs/concepts/configuration#yaml-configuration) describes every key.

When the file has a weave section, its values win over `WithConfig` and the other programmatic options, which only fill fields the file leaves empty. `WithDisableRoutes` and `WithDisableMigrate` always turn their flag on.

```go
weaveext.New(
    weaveext.WithRequireConfig(true), // Register fails without a weave config section
)
```

## Getting the engine elsewhere

Other extensions and your handlers resolve the engine from the container:

```go
eng, err := forge.Inject[*engine.Engine](app.Container())
if err != nil {
    log.Fatal(err)
}
```

If you kept the extension value, its `Engine()` method returns the same engine once `Register` has run, and `nil` before.

## Tenants

The routes pass the request context to the engine, so set the tenant there with a global middleware:

```go
app.Router().UseGlobal(func(next forge.Handler) forge.Handler {
    return func(ctx forge.Context) error {
        tenantID := ctx.Request().Header.Get("X-Tenant-ID") // or from your auth claims
        ctx.WithContext(weave.WithTenant(ctx.Context(), tenantID))
        return next(ctx)
    }
})
```

Only creates, ingests and searches use the tenant. The list, get, delete, stats and reindex routes don't check it; see [multi-tenancy](/docs/concepts/multi-tenancy).

## Metrics

To get the counters into your app's metrics output, build the metrics extension from the app's metrics. That needs the app first, so register Weave after `NewApp`:

```go
app := forge.NewApp(forge.AppConfig{Name: "search-api"})

err := app.RegisterExtension(weaveext.New(
    weaveext.WithStore(memory.New()),
    weaveext.WithVectorStore(vsmemory.New()),
    weaveext.WithEngineOption(engine.WithEmbedder(
        embedder.NewOpenAIEmbedder(os.Getenv("OPENAI_API_KEY")),
    )),
    weaveext.WithEngineOption(engine.WithChunker(chunker.NewRecursiveChunker())),
    weaveext.WithExtension(observability.NewMetricsExtensionWithFactory(app.Metrics())),
))
if err != nil {
    log.Fatal(err)
}
```

## Dashboard

The extension implements Forge's dashboard contract contributor (`RegisterContractContributor`), so when you run the Forge dashboard it discovers a Weave section on start.
