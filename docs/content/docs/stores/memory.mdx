---
title: In-Memory Store
description: In-memory metadata store and vector store for development, testing and prototyping.
---

Weave ships two in-memory stores: one for metadata (collections, documents, chunks) and one for vectors. Neither has dependencies, and both lose everything when the process exits.

## Metadata store

```go
import "github.com/xraph/weave/store/memory"

st := memory.New()
```

`memory.Store` implements `store.Store`. It keeps entities in Go maps behind a `sync.RWMutex` and follows the same rules as the database stores: collection names are unique per tenant, the same content hash can't appear twice in a collection, and list filters apply `Tenant` only when you set it.

## Vector store

```go
import vsmemory "github.com/xraph/weave/vectorstore/memory"

vs := vsmemory.New()
```

`vectorstore/memory.Store` implements `vectorstore.VectorStore`. It keeps entries in a map and scores every one on each `Search` with cosine similarity, applying the metadata filter and `tenant_id` as exact matches. Ties are broken by ID, so the order is stable. With no `TopK` it returns 10.

## Using both together

```go
import (
    "github.com/xraph/weave/chunker"
    "github.com/xraph/weave/engine"
    "github.com/xraph/weave/store/memory"
    vsmemory "github.com/xraph/weave/vectorstore/memory"
)

eng, err := engine.New(
    engine.WithStore(memory.New()),
    engine.WithVectorStore(vsmemory.New()),
    engine.WithEmbedder(emb),
    engine.WithChunker(chunker.NewRecursiveChunker()),
)
```

## Lifecycle

| Method | Behaviour |
|--------|-----------|
| `Migrate(ctx)` | Does nothing |
| `Ping(ctx)` | Returns `nil` |
| `Close()` | Does nothing |

## Limitations

- Nothing is persisted.
- Each `New()` is independent, so several processes can't share one.
- Search is a full scan over every vector, which is fine for tests and small data sets and slow for large ones.

## Moving to PostgreSQL

The stores implement the same interfaces, so the switch happens where you build the engine:

```go
// Development
eng, err := engine.New(
    engine.WithStore(memory.New()),
    engine.WithVectorStore(vsmemory.New()),
    engine.WithEmbedder(emb),
    engine.WithChunker(chunker.NewRecursiveChunker()),
)

// Production
eng, err = engine.New(
    engine.WithStore(postgres.New(db)),
    engine.WithVectorStore(pgvector.New(db)),
    engine.WithEmbedder(emb),
    engine.WithChunker(chunker.NewRecursiveChunker()),
)
```

Remember the extra steps on the production side: call `Migrate` on the Postgres store and create the pgvector table yourself, see [PostgreSQL store](/docs/stores/postgres#pgvector).
