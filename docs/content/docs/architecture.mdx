Weave is a set of small Go packages around one coordinator, `engine.Engine`. The engine owns no storage or model code of its own: you hand it a metadata store, a vector store, an embedder, a chunker and, optionally, a loader and a retriever, and it calls them in order.

## Package diagram

```
+------------------------------------------------------------------+
|                         engine.Engine                            |
|  CreateCollection / GetCollection / ListCollections /            |
|  UpdateCollection / DeleteCollection / CollectionStats           |
|  Ingest / IngestBatch / GetDocument / ListDocuments /            |
|  DeleteDocument / ReindexCollection                              |
|  Retrieve / HybridSearch / RetrieveCompare / Assemble            |
+-------------------------------+----------------------------------+
|  plugins.Registry             |  loader.Loader (optional)        |
|  14 lifecycle hooks           |  chunker.Chunker                 |
|  (observability, audit_hook)  |  embedder.Embedder               |
|                               |  retriever.Retriever (optional)  |
+-------------------------------+----------------------------------+
|                          store.Store                             |
|  collection.Store + document.Store + chunk.Store                 |
|  + Migrate / Ping / Close                                        |
+-------------+---------------+---------------+--------------------+
| store/memory| store/postgres| store/sqlite  | store/mongo        |
+-------------+---------------+---------------+--------------------+
|                    vectorstore.VectorStore                       |
|  Upsert / Search / Delete / DeleteByMetadata                     |
+---------------------+--------------------------+-----------------+
| vectorstore/memory  | vectorstore/pgvector     | vectorstore/    |
|                     |                          | fabriq          |
+---------------------+--------------------------+-----------------+
```

The `extension` and `api` packages sit on top: `api` turns engine calls into Forge routes, and `extension` wires the engine and the routes into a Forge app. They're the only packages that import Forge.

## Engine construction

`engine.New` takes option functions:

```go
eng, err := engine.New(
    engine.WithStore(st),                     // needed for every operation
    engine.WithVectorStore(vs),               // needed to ingest and retrieve
    engine.WithEmbedder(emb),                 // needed to ingest and retrieve
    engine.WithChunker(chunker.NewRecursiveChunker()), // needed to ingest
    engine.WithLoader(loader.NewMarkdownLoader()),     // optional
    engine.WithRetriever(r),                  // optional
    engine.WithExtension(observability.NewMetricsExtension()), // optional, repeatable
    engine.WithLogger(logger),                // optional, a go-utils log.Logger
    engine.WithMetrics(sink),                 // optional, a go-utils metrics sink
    engine.WithConfig(weave.DefaultConfig()), // optional
)
```

`New` itself never fails for a missing part. Each operation checks what it needs when you call it. See [configuration](/docs/concepts/configuration) for every option.

## Ingestion pipeline

`engine.Ingest` runs these steps in order:

1. Check that the store, embedder, vector store and chunker are set and that `Content` isn't empty.
2. Read the collection, for its chunk size, overlap and strategy.
3. Hash the content with SHA-256 and create the document with `State=pending` and the tenant from the context. A document with the same hash already in the collection makes this fail with `ErrDuplicateDocument`.
4. Fire `OnIngestStarted`, then set `State=processing`.
5. If a loader is configured and `IngestInput.SourceType` is a type it supports, run the content through it.
6. Chunk the content and fire `OnIngestChunked`.
7. Embed every chunk in one `Embed` call and fire `OnIngestEmbedded`.
8. Write the chunks to the metadata store with `CreateChunkBatch`.
9. Upsert one vector per chunk. Its ID is the chunk ID and its metadata carries `collection_id`, `document_id`, `tenant_id` and `chunk_index`, plus the chunk's own metadata.
10. Set `State=ready` and `ChunkCount`, then fire `OnIngestCompleted`.

If step 5 or anything after it fails, the document is set to `failed` with the error text in `Error`, and `OnIngestFailed` fires.

## Retrieval pipeline

`engine.Retrieve` runs:

1. Fire `OnRetrievalStarted`.
2. Build a filter: `collection_id` from `WithCollection`, and `tenant_id` from `WithTenantFilter`, `WithTenantID` or the context tenant, in that order.
3. If a retriever is configured, call it with that filter. Otherwise embed the query and call `VectorStore.Search` directly.
4. Read each hit's chunk back from the metadata store by ID. A hit whose chunk row is gone stays in the results with `Orphaned` set.
5. Fire `OnRetrievalCompleted`, or `OnRetrievalFailed` on an error.

## Extension system

Extensions are any value with a `Name() string` method. The engine type-asserts each one against 14 hook interfaces (`CollectionCreated`, `IngestCompleted`, `RetrievalFailed` and so on) and calls only the hooks it implements. A hook that returns an error is logged at warn level and never stops the operation. See [extension system](/docs/subsystems/plugins).

The `ext` and `plugins` packages hold the same interfaces. `engine.WithExtension` is typed with `ext.Extension` and the registry uses `plugins`; because the interfaces are identical, a value that satisfies one satisfies the other.
