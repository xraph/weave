## Engine options

`engine.New` takes a variadic list of options:

```go
eng, err := engine.New(
    engine.WithStore(st),
    engine.WithVectorStore(vs),
    engine.WithEmbedder(emb),
    engine.WithChunker(chunker.NewRecursiveChunker()),
    engine.WithLoader(loader.NewMarkdownLoader()),
    engine.WithRetriever(r),
    engine.WithExtension(observability.NewMetricsExtension()),
    engine.WithLogger(logger),
    engine.WithMetrics(sink),
    engine.WithConfig(weave.DefaultConfig()),
)
```

| Option | Type | Default | What happens without it |
|--------|------|---------|-------------------------|
| `WithStore(s)` | `store.Store` | none | Every collection and document call returns `weave.ErrNoStore` |
| `WithVectorStore(v)` | `vectorstore.VectorStore` | none | `Ingest` and `ReindexCollection` return `ErrNoVectorStore`; `Retrieve` fails unless you set a retriever |
| `WithEmbedder(e)` | `embedder.Embedder` | none | `Ingest` and `ReindexCollection` return `ErrNoEmbedder`; `Retrieve` fails unless you set a retriever |
| `WithChunker(c)` | `chunker.Chunker` | none | `Ingest` returns `ErrNoChunker` |
| `WithLoader(l)` | `loader.Loader` | none | Content is chunked as it is |
| `WithRetriever(r)` | `retriever.Retriever` | none | `Retrieve` embeds the query and searches the vector store directly |
| `WithExtension(x)` | `ext.Extension` | none | Repeatable; adds a lifecycle hook |
| `WithLogger(l)` | go-utils `log.Logger` | a no-op logger | Nothing is logged |
| `WithMetrics(m)` | go-utils `metrics.Metrics` | none | No metrics are recorded; spans still go to the global tracer provider. See [observability](/docs/subsystems/observability) |
| `WithConfig(cfg)` | `weave.Config` | `weave.DefaultConfig()` | The defaults below apply |

There's no default chunker or embedder. You always pass both.

## weave.Config

```go
weave.Config{
    DefaultChunkSize:      512,
    DefaultChunkOverlap:   50,
    DefaultEmbeddingModel: "text-embedding-3-small",
    DefaultChunkStrategy:  "recursive",
    DefaultTopK:           10,
    ShutdownTimeout:       30 * time.Second,
    IngestConcurrency:     4,
}
```

That's what `weave.DefaultConfig()` returns. `WithConfig` replaces the whole struct, so start from `DefaultConfig()` and change the fields you want.

| Field | Used by |
|-------|---------|
| `DefaultChunkSize`, `DefaultChunkOverlap` | `CreateCollection`, for a collection that leaves `ChunkSize` or `ChunkOverlap` at zero. Ingest then chunks with the collection's values. |
| `DefaultEmbeddingModel`, `DefaultChunkStrategy` | `CreateCollection` records them on the collection. Nothing else reads them: the embedder and chunker you configured run whatever the collection says. |
| `DefaultTopK` | `Retrieve` and `HybridSearch` when you don't set a top K |
| `ShutdownTimeout` | Nothing yet |
| `IngestConcurrency` | Nothing yet. `IngestBatch` ingests one document at a time. |

Sizes are in tokens, and the built-in chunkers treat a token as four characters.

## Per-collection settings

Each collection keeps its own chunk settings, and ingest uses them:

```go
col := &collection.Collection{
    Name:          "legal-docs",
    ChunkSize:     1024,
    ChunkOverlap:  100,
    EmbeddingDims: 3072,
    Metadata:      map[string]string{"domain": "legal"},
}
err := eng.CreateCollection(ctx, col)
```

Only `ChunkSize` and `ChunkOverlap` change how documents are processed. `EmbeddingModel`, `EmbeddingDims` and `ChunkStrategy` are stored for your reference. If you want a different model or chunker for one collection, build a separate engine for it.

`UpdateCollection` can change a collection's name, description and metadata after the fact. It deliberately can't change the chunk or embedding settings, because Weave can't re-chunk documents that are already in.

## Forge extension options

```go
ext := extension.New(
    extension.WithStore(st),
    extension.WithVectorStore(vs),
    extension.WithEngineOption(engine.WithEmbedder(emb)),
    extension.WithEngineOption(engine.WithChunker(chunker.NewRecursiveChunker())),
    extension.WithExtension(observability.NewMetricsExtension()),
    extension.WithBasePath("/weave"),
)
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `WithStore(s)` | `store.Store` | none | Metadata store. A `*grove.DB` in the container replaces it, see below. |
| `WithVectorStore(v)` | `vectorstore.VectorStore` | none | Vector store |
| `WithEngineOption(opt)` | `engine.Option` | none | Any engine option. This is how you pass the embedder, chunker, loader and retriever. |
| `WithExtension(x)` | `plugins.Extension` | none | Lifecycle hook, repeatable |
| `WithConfig(cfg)` | `extension.Config` | `extension.DefaultConfig()` | Whole config struct |
| `WithBasePath(path)` | `string` | `"/weave"` | Route prefix |
| `WithDisableRoutes()` | | off | Don't mount the HTTP routes |
| `WithDisableMigrate()` | | off | Don't run `Migrate` on `Start` |
| `WithGroveDatabase(name)` | `string` | `""` | Resolve a `*grove.DB` from the container (by name, or the default one for `""`) and build the matching store |
| `WithRequireConfig(b)` | `bool` | `false` | Fail `Register` when no `extensions.weave` or `weave` key is in the config |

The extension has no embedder or chunker option of its own.

Store resolution happens in `Register`. With `WithGroveDatabase` (or `grove_database` in YAML) the extension resolves that database and fails if it isn't there. Without it, the extension looks for a default `*grove.DB` in the container anyway and, if it finds one, uses it. Either way it builds a `postgres`, `sqlite` or `mongo` store from the driver name, and that store wins over one you passed with `WithStore`. If there's no grove database and no `WithStore`, the engine has no store, and `Start` skips the migration.

## YAML configuration

The extension reads `extensions.weave` and falls back to a top-level `weave` key:

```yaml
extensions:
  weave:
    base_path: /weave
    disable_routes: false
    disable_migrate: false
    grove_database: ""
    default_chunk_size: 512
    default_chunk_overlap: 50
    default_embedding_model: text-embedding-3-small
    default_chunk_strategy: recursive
    default_top_k: 10
    shutdown_timeout: 30s
    ingest_concurrency: 4
    recovery_interval: 5m
    stalled_after: 15m
```

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `base_path` | string | `/weave` | Route prefix |
| `disable_routes` | bool | `false` | Skip route registration |
| `disable_migrate` | bool | `false` | Skip `Migrate` on `Start` |
| `grove_database` | string | `""` | Named `*grove.DB` to build the store from |
| `default_chunk_size` | int | `512` | Engine `DefaultChunkSize` |
| `default_chunk_overlap` | int | `50` | Engine `DefaultChunkOverlap`; must be smaller than `default_chunk_size` or `Register` fails |
| `default_embedding_model` | string | `text-embedding-3-small` | Recorded on new collections |
| `default_chunk_strategy` | string | `recursive` | Recorded on new collections |
| `default_top_k` | int | `10` | Engine `DefaultTopK` |
| `shutdown_timeout` | duration | `30s` | Not used yet |
| `ingest_concurrency` | int | `4` | Not used yet |
| `recovery_interval` | duration | `5m` | How often the engine sweeps for documents a crash left behind (see [Recovery](/docs/subsystems/ingestion#recovery)). Negative turns the loop off, for a host that calls `RecoverStalled` from its own scheduler |
| `stalled_after` | duration | `15m` | How long a `pending` or `processing` document can go without a heartbeat before recovery fails it and a keyed ingest of the same content may claim it. Keep it well above your slowest embed call. Negative fails `Register` |

### Merge behaviour

When the config file has a weave section, its values win. A programmatic value only fills a field the file leaves empty or zero, and `WithDisableRoutes` and `WithDisableMigrate` turn their flag on whatever the file says. Anything still zero after that gets the default. When the file has no weave section, your programmatic config is used with the defaults filled in.

An engine option passed with `WithEngineOption(engine.WithConfig(...))` is applied after the extension's own config, so it wins.
