Every Weave component is a Go interface. This guide shows how to implement each one so you can plug in custom backends, models, or processing logic.

## Custom Chunker

Implement `chunker.Chunker` to split text with your own algorithm:

```go
import "github.com/xraph/weave/chunker"

type SentenceChunker struct {
    maxTokens int
}

func (c *SentenceChunker) Chunk(_ context.Context, text string, opts *chunker.Options) ([]chunker.ChunkResult, error) {
    sentences := splitSentences(text)
    var results []chunker.ChunkResult
    var current strings.Builder
    idx := 0

    for _, sentence := range sentences {
        if estimateTokens(current.String()) + estimateTokens(sentence) > opts.ChunkSize {
            if current.Len() > 0 {
                results = append(results, chunker.ChunkResult{
                    Content:    current.String(),
                    Index:      idx,
                    TokenCount: estimateTokens(current.String()),
                })
                idx++
                current.Reset()
            }
        }
        current.WriteString(sentence + " ")
    }
    if current.Len() > 0 {
        results = append(results, chunker.ChunkResult{
            Content:    strings.TrimSpace(current.String()),
            Index:      idx,
            TokenCount: estimateTokens(current.String()),
        })
    }
    return results, nil
}

// Register:
eng, _ := engine.New(engine.WithChunker(&SentenceChunker{maxTokens: 256}))
```

## Custom Embedder

Implement `embedder.Embedder` to use any embedding model:

```go
import "github.com/xraph/weave/embedder"

type CohereEmbedder struct {
    client *cohere.Client
    dims   int
}

func (e *CohereEmbedder) Embed(ctx context.Context, texts []string) ([]embedder.EmbedResult, error) {
    resp, err := e.client.Embed(ctx, &cohere.EmbedRequest{
        Texts:     texts,
        Model:     "embed-english-v3.0",
        InputType: "search_document",
    })
    if err != nil {
        return nil, err
    }
    results := make([]embedder.EmbedResult, len(resp.Embeddings))
    for i, vec := range resp.Embeddings {
        results[i] = embedder.EmbedResult{Vector: toFloat32(vec)}
    }
    return results, nil
}

func (e *CohereEmbedder) Dimensions() int { return e.dims }

// Register:
eng, _ := engine.New(engine.WithEmbedder(&CohereEmbedder{client: client, dims: 1024}))
```

## Custom Loader

Implement `loader.Loader` to extract text from a custom format:

```go
import (
    "io"
    "github.com/xraph/weave/loader"
)

type DocxLoader struct{}

func (l *DocxLoader) Supports(mime string) bool {
    return mime == "application/vnd.openxmlformats-officedocument.wordprocessingml.document"
}

func (l *DocxLoader) Load(ctx context.Context, r io.Reader) (*loader.LoadResult, error) {
    data, err := io.ReadAll(r)
    if err != nil {
        return nil, err
    }
    text, meta, err := extractDocx(data)
    if err != nil {
        return nil, fmt.Errorf("docx: %w", err)
    }
    return &loader.LoadResult{
        Content:  text,
        MimeType: "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
        Metadata: meta,
    }, nil
}

// Register:
eng, _ := engine.New(engine.WithLoader(&DocxLoader{}))
```

When ingesting a `.docx` file, set `SourceType` to trigger the loader:

```go
eng.Ingest(ctx, &engine.IngestInput{
    CollectionID: colID,
    Content:      string(docxBytes),
    SourceType:   "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
})
```

## Custom VectorStore

Implement `vectorstore.VectorStore` to use any vector database:

```go
import "github.com/xraph/weave/vectorstore"

type WeaviateStore struct {
    client *weaviate.Client
}

func (s *WeaviateStore) Upsert(ctx context.Context, entries []vectorstore.Entry) error {
    objects := make([]*models.Object, len(entries))
    for i, e := range entries {
        objects[i] = &models.Object{
            ID:         strfmt.UUID(e.ID),
            Class:      "WeaveChunk",
            Vector:     toFloat64(e.Vector),
            Properties: e.Metadata,
        }
    }
    _, err := s.client.Batch().ObjectsBatcher().WithObjects(objects...).Do(ctx)
    return err
}

func (s *WeaviateStore) Search(ctx context.Context, vector []float32, opts *vectorstore.SearchOptions) ([]vectorstore.SearchResult, error) {
    // ... weaviate nearVector query
}

func (s *WeaviateStore) Delete(ctx context.Context, ids []string) error { /* ... */ }
func (s *WeaviateStore) DeleteByMetadata(ctx context.Context, filter map[string]string) error { /* ... */ }

// Register:
eng, _ := engine.New(engine.WithVectorStore(&WeaviateStore{client: weaviateClient}))
```

The engine relies on a few things from a vector store:

- `Search` applies every key in `opts.Filter` as an exact metadata match (the engine sends `tenant_id`, and `collection_id` when the caller names one) and refuses an empty `TenantKey` with `weave.ErrTenantRequired`. There's no search across tenants.
- `Upsert` refuses a batch with any entry lacking `metadata["tenant_id"]` with `weave.ErrTenantRequired`, before it writes any of it.
- `SearchResult.ID` is the entry ID you were given, which is the chunk ID. The engine reads the chunk back by it.
- `DeleteByMetadata` deletes every entry matching all the pairs, and refuses an empty filter with `weave.ErrInvalidArgument`. Document and collection deletes call it with `tenant_id` next to `document_id` or `collection_id`.
- Return `SearchResult.Vector` if you can. The MMR retriever needs it.

The engine also drops any hit labelled with another tenant, but a store that skips the filter then hands back short pages, so apply it.

## Custom MetadataStore

Implement `store.Store` (which embeds `collection.Store`, `document.Store`, `chunk.Store`) to use a different database:

```go
import "github.com/xraph/weave/store"

// Your struct must implement all methods from:
// - collection.Store (CreateCollection, GetCollection, ListCollections, DeleteCollection, ...)
// - document.Store (CreateDocument, GetDocument, UpdateDocument, ListDocuments, DeleteDocument, ...)
// - chunk.Store (CreateChunkBatch, ListChunksByDocument, DeleteChunksByDocument, ...)
// - store.Store (ReplaceSourceDocument, TouchDocument, FailDocument,
//   ListStalledDocuments, CountStalledUntenanted, Migrate, Ping, Close)

type MyStore struct{ /* ... */ }

var _ store.Store = (*MyStore)(nil) // compile-time check

eng, _ := engine.New(engine.WithStore(&MyStore{}))
```

See [store/store.go](https://github.com/xraph/weave/blob/main/store/store.go) for the full interface definition.

### Tenant rules

Weave relies on the store to keep tenants apart, so your store has to do what the built-in ones do. Go through this list before you ship one:

- Every method except `Migrate`, `Ping`, `Close`, `ListStalledDocuments` and `CountStalledUntenanted` reads the tenant from the context first, with `weave.RequireTenant(ctx)`. No tenant means `weave.ErrTenantRequired`, returned before any query runs.
- `ListStalledDocuments` is the one exception, and it's deliberate. Recovery is an operator's sweep, so it needs one read across tenants to find what a crash left behind. It works with no tenant on the context and returns each row with its `TenantID`, and the engine then handles each document under that tenant, so every later call is scoped as usual. `CountStalledUntenanted` needs no tenant either, but it only counts rows that belong to none. Don't add another method like these two.
- Get, update and delete by ID match on the tenant as well as the ID (`WHERE id = $1 AND tenant_id = $2` in SQL, a `tenant_id` key in a Mongo filter). A row that belongs to another tenant returns `ErrCollectionNotFound`, `ErrDocumentNotFound` or `ErrChunkNotFound`, the same as an ID that doesn't exist. Never a different error, or IDs leak what exists.
- An update checks the stored row's tenant, not just the `TenantID` on the struct it's given, so a caller can't move a row into its own tenant by relabelling it.
- `DeleteChunksByDocument`, `DeleteChunksByCollection`, `DeleteDocumentsByCollection`, `ListChunksByDocument` and every list and count add the tenant predicate too. Pointed at another tenant's collection or document, the deletes succeed and remove nothing.
- `CreateCollection`, `CreateDocument` and `CreateChunkBatch` refuse an entity whose `TenantID` isn't the context tenant with `weave.ErrInvalidArgument`. For a batch, check every chunk before you write any of them.
- A row only hangs off a parent of its own tenant. `CreateDocument` checks that the document's collection belongs to the context tenant, and `CreateChunkBatch` does the same for each chunk's document. Another tenant's parent and an unknown ID both get `ErrCollectionNotFound` or `ErrDocumentNotFound`, checked before anything else, so a create can't tell you which IDs exist or what content they hold. Do the check in the same transaction as the insert if your database has them. Without it, a collection delete that cascades would take another tenant's rows with it.
- A chunk's `CollectionID` must be its document's, else `ErrInvalidArgument`, and `UpdateDocument` never moves a document to another collection: match on `collection_id` as well and answer not-found when it differs.
- A batch that reuses a chunk ID already stored, by any tenant, or repeats one, fails as a whole. Never upsert a chunk.
- `GetCollectionByName(ctx, tenantID, name)` refuses a `tenantID` that isn't the context tenant with `weave.ErrInvalidArgument`.
- The deprecated `Tenant *string` on list and count filters must equal the context tenant when it's set. Anything else, `""` included, is `weave.ErrInvalidArgument`.

Treat `""` as no tenant everywhere. Rows a v1.8 install wrote with an empty tenant must stay unreachable.

### Replacing a source's document

`ReplaceSourceDocument(ctx, doc, chunks)` finishes the ingest of a new version of a source. It's the one store method that changes several rows at once, and it has to be atomic: a reader sees the old version or the new one, never both and never neither. Your store has to do all of this:

- Check the tenant first, like every other method. Then read the stored document under the context tenant, inside the same transaction as the writes. Missing, another tenant's, or in another collection than `doc.CollectionID` is `ErrDocumentNotFound`.
- `doc.SourceKey` empty, or different from the stored one, is `ErrInvalidArgument`. So is a chunk whose tenant, document or collection isn't `doc`'s.
- The stored document must be `processing`. Anything else is `ErrInvalidState`, returned before you write anything.
- Mark every `ready` or `failed` document with the same tenant, collection and source key `superseded`, delete their chunks, insert `chunks`, and move `doc` to `ready` with `ChunkCount` set to `len(chunks)`. Return the superseded IDs.
- If any step fails, none of it sticks. A chunk ID that repeats inside the batch or already exists (the superseded version's included) fails the call.
- Concurrent replaces of one source must serialize. Six replicas replacing the same source at once all succeed, and the source ends with one `ready` document, the last to finish. The built-in stores take a Postgres advisory lock on tenant, collection and key, hold a writer mutex on SQLite, retry Mongo's transaction on a write conflict, and run under the mutex in memory.

A unique index on `(collection_id, source_key)` over ready, keyed rows is a good backstop. The built-in SQL and Mongo stores have one.

### Heartbeats and recovery

Two methods let ingest and [recovery](/docs/subsystems/ingestion#recovery) move a document's state without stepping on each other, and a third finds the documents recovery should look at. Each move is a single guarded write, a compare-and-set on the stored state. A read followed by an update leaves a gap another replica can land in.

- `TouchDocument(ctx, docID, staleBefore)` moves a `pending` or `processing` document to `processing` and sets `UpdatedAt` to now. With a non-zero `staleBefore` it only does that when the stored `UpdatedAt` is older than `staleBefore`. That's what makes a claim safe: when eight replicas find one stalled document, exactly one touch matches and the other seven get `ErrInvalidState`.
- `FailDocument(ctx, docID, errText, staleBefore)` moves a `pending` or `processing` document to `failed` with `Error` set to `errText`, under the same `staleBefore` rule. It must never touch a `ready` document, because that's how a failing attempt is kept from overwriting a version another attempt has just finished.
- Both answer `ErrInvalidState` for a document in any other state, or one updated since `staleBefore`, and `ErrDocumentNotFound` for a missing document or another tenant's. Neither writes anything when it refuses.
- `ListStalledDocuments(ctx, before, limit)` returns `pending`, `processing` and `superseded` documents with `UpdatedAt` before `before`, from every tenant, oldest first by `UpdatedAt` then ID. Leave out rows with an empty tenant: recovery can't scope them, and v1.8 installs can hold enough of them to fill every batch. A `limit` of zero or less means 100. An index on `(state, updated_at)` keeps it cheap; the built-in stores add one in migration `20261024000200`.
- `CountStalledUntenanted(ctx, before)` counts exactly the rows that rule leaves out: same states, same age, empty tenant. Recovery only reports the number.

In SQL each of the two moves is one `UPDATE ... WHERE id = $1 AND tenant_id = $2 AND state IN ('pending', 'processing') AND updated_at < $3`, and zero rows affected means you read the row once to tell not-found from the wrong state. In Mongo it's one `UpdateOne` with the same filter.

### Testing a custom store

`store/storetest` is the conformance suite the built-in stores run. Point it at yours from a test:

```go
func TestMyStore(t *testing.T) {
    storetest.Run(t, func(t *testing.T) store.Store {
        return newMyStore(t)
    })
}
```

It checks filters, ordering, duplicates, timestamps and nil metadata handling, every rule in the list above, the replace contract, concurrent replaces included, and the heartbeat and recovery methods, with concurrent claims of one document. `storetest.RunLegacy(t, open, plant)` adds the cases that need rows only a v1.8 install could write; `plant` writes a document as it is, bypassing your store's checks. The tenant cases call every method with no tenant, and try each read, update and delete as one tenant with another tenant's IDs. When `store.Store` gains a method, the tenant case fails until it covers that method too.
