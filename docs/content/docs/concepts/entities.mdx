---
title: Entities
description: The core data types in Weave, Collection, Document and Chunk.
---

Weave works with three entities. Collections and documents embed `weave.Entity`, which holds `CreatedAt` and `UpdatedAt`. Chunks have only `CreatedAt`.

## Collection

A collection is a named group of documents that share chunk settings.

```go
// package collection
type Collection struct {
    weave.Entity

    ID             id.CollectionID   // col_...
    Name           string
    Description    string
    TenantID       string
    AppID          string
    EmbeddingModel string            // recorded, e.g. "text-embedding-3-small"
    EmbeddingDims  int               // recorded, e.g. 1536
    ChunkStrategy  string            // recorded, e.g. "recursive"
    ChunkSize      int               // tokens, used by ingest
    ChunkOverlap   int               // tokens, used by ingest
    Metadata       map[string]string
    DocumentCount  int64             // never updated, see below
    ChunkCount     int64             // never updated, see below
}
```

`CreateCollection` sets the ID, takes `TenantID` and `AppID` from the context when they're empty, and fills zero chunk settings and an empty model or strategy from the engine config. It doesn't set `EmbeddingDims`.

Names are unique per tenant. A second collection with the same name under the same tenant fails with `weave.ErrCollectionAlreadyExists`.

Only `ChunkSize` and `ChunkOverlap` change how documents are processed. The model, dimensions and strategy are stored for your reference; the engine's embedder and chunker run regardless.

`DocumentCount` and `ChunkCount` exist on the struct and in the tables but nothing updates them, so they stay at zero. Call `eng.CollectionStats(ctx, colID)` for live counts.

`eng.UpdateCollection(ctx, colID, engine.CollectionUpdate{...})` changes `Name`, `Description` and `Metadata`. The chunk and embedding settings can't be changed after creation.

## Document

A document is one piece of content ingested into a collection. Its `State` follows the ingest.

```go
// package document
type Document struct {
    weave.Entity

    ID            id.DocumentID     // doc_...
    CollectionID  id.CollectionID
    TenantID      string
    Title         string
    Source        string            // file name, URL or identifier
    SourceType    string            // MIME type
    ContentHash   string            // hex SHA-256 of the raw content
    ContentLength int               // bytes
    ChunkCount    int
    Metadata      map[string]string
    State         document.State    // pending | processing | ready | failed
    Error         string            // set when State is failed
}
```

Documents carry a tenant but no app ID. The document doesn't keep the content itself; the chunks do.

### Document states

| State | Meaning |
|-------|---------|
| `pending` | Created, not yet processed |
| `processing` | Being loaded, chunked and embedded |
| `ready` | Fully processed and searchable |
| `failed` | Ingestion failed; `Error` says why |

On success a document goes `pending`, `processing`, `ready`. On a failure after it was created, it ends up `failed` and stays in the store until you delete it.

`ContentHash` is unique per collection. Ingesting the same content into the same collection again fails with `weave.ErrDuplicateDocument`, and that includes content whose earlier ingest failed.

## Chunk

A chunk is a piece of a document's text. Chunks are what gets embedded, stored as vectors and retrieved.

```go
// package chunk
type Chunk struct {
    ID           id.ChunkID        // chk_...
    DocumentID   id.DocumentID
    CollectionID id.CollectionID
    TenantID     string
    Content      string
    Index        int               // position within the document
    StartOffset  int               // byte offset in the loaded text
    EndOffset    int
    TokenCount   int               // estimate
    Metadata     map[string]string // from the chunker
    ParentID     string            // not set by the built-in chunkers
    CreatedAt    time.Time
}
```

Each chunk's vector has the same ID as the chunk, which is how retrieval maps a vector hit back to its row. Chunks aren't edited after creation. To change a document's chunks, delete the document and ingest it again. To change only the vectors, call `eng.ReindexCollection(ctx, colID)`.

## ScoredChunk

`Retrieve` and `HybridSearch` return `[]engine.ScoredChunk`:

```go
type ScoredChunk struct {
    Chunk    *chunk.Chunk
    Score    float64
    Hydrated bool // Chunk was read back from the metadata store
    Orphaned bool // the vector exists, the chunk row doesn't
}
```

Hits are sorted best first. Filter weak ones with `engine.WithMinScore`:

```go
hits, err := eng.Retrieve(ctx, "refund timeline",
    engine.WithCollection(colID),
    engine.WithTopK(10),
    engine.WithMinScore(0.3),
)
```

With the in-memory and pgvector stores the score is cosine similarity. Other retrievers produce other scores, see [semantic retrieval](/docs/subsystems/retrieval#scoredchunk).
